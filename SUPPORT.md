# Getting help

Every kind of message has one place to go, so it reaches the people who can act on it and
the next person with the same question can find the answer.

| You have | Where it goes |
|---|---|
| A bug, or something that looks wrong | **GitHub Issues** in the app's repository. In the app, Help > Report a Bug opens one with the version filled in. |
| An idea or a missing feature | **GitHub Issues** in the app's repository, as a feature request. Tell us the production task you're trying to do; that helps more than a description of a button. |
| A question, an idea to talk through, or something you made | **[GitHub Discussions](https://github.com/method-production-suite/.github/discussions)**: Q&A for questions, Ideas, and Show and tell. |
| A security problem | **Privately**, through GitHub's private vulnerability reporting, as [SECURITY.md](SECURITY.md) describes. Never in a public issue or discussion. |
| A conduct problem | **conduct@methodproduction.com**, privately, as the [Code of Conduct](CODE_OF_CONDUCT.md) describes. |
| Press, schools and partnerships | **hello@methodproduction.com** |

Please don't email bug reports, and never send a real script, budget or schedule; an
invented file that shows the problem is always enough.

Before you ask, the app's README and its `docs/` folder may already have the answer. If
they don't, asking is welcome: a missing answer is a gap in the docs.

The apps are free, and there is no paid support or guaranteed response time. They are
tools, not legal, payroll or accounting advice: check figures that matter, such as union
rates or fringes, against their source.
